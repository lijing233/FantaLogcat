# FantaLogcat 产品与技术设计

- 状态：已确认
- 日期：2026-08-11
- 目标版本：1.0
- 平台：macOS 13+，Apple Silicon（arm64）

## 1. 背景

Unity Android 游戏开发过程中，Android Studio 仅用于查看 Logcat 过于笨重；直接使用 `adb logcat` 又要求用户记忆设备、进程和筛选命令。FantaLogcat 提供一个轻量、开箱易用的 macOS 图形工具，让不了解 ADB 的开发者或测试人员也能快速连接设备、选择应用、查看和分享日志。

产品首先服务个人高频开发，随后供团队内部使用，最终在 GitHub 开源。实现和发布标准按成熟桌面产品设计。

## 2. 产品原则

1. **任务优先**：用户只需理解“连接设备、选择应用、查看日志”。ADB、PID、buffer 等术语默认隐藏。
2. **本地优先**：日志、筛选和配置均在本机处理，不上传服务器，不引入账号或遥测。
3. **轻量稳定**：启动快、内存有界，日志洪峰、导出和设备重连不阻塞界面。
4. **渐进增强**：常见操作直接可见；正则、原始 Tag、系统 ADB 等能力按需展开。
5. **可解释**：连接、筛选、缓存回收和导出范围始终清楚，不静默丢弃或截断。
6. **公开与内部隔离**：团队预设可注入内部构建，但公开源码与公开构建默认不包含内部信息。

## 3. 目标用户与成功标准

### 3.1 目标用户

- 主要用户：开发 Unity Android 游戏、经常查看业务库与插件日志的开发者。
- 次要用户：团队内测试人员和不熟悉 ADB 的开发者。
- 开源用户：需要比 Android Studio 更轻、比命令行更易用的 Android 开发者。

### 3.2 成功标准

- 新用户安装后 1 分钟内完成设备连接并看到目标应用日志。
- 常用用户启动后 10 秒内开始查看指定应用。
- 默认流程不要求用户输入或理解任何 ADB 命令。
- 连续采集数小时不出现明显卡顿或失控的内存增长。
- 导出的范围、条数和是否脱敏均可预览和复核。

## 4. 范围

### 4.1 1.0 包含

- 单个活跃设备。
- USB ADB 与 Android 11+ 无线调试配对。
- 应用管理的官方 ADB：首次使用时一键下载安装，无需 Android Studio。
- 常用应用、设备第三方应用搜索和临时包名输入。
- 以当前应用为默认视图，并可切换全设备日志。
- 自动跟踪应用主进程及 `包名:进程名` 子进程。
- 日志等级、Android Tag、消息业务 Tag、关键词、排除词和正则筛选。
- Unity、Android 异常、ANR、IncentiveEngine 等内置筛选方案。
- 自定义命名筛选方案，以及应用与筛选配置的导入、导出、合并。
- 团队构建时注入常用应用和筛选预设。
- 暂停显示、自动跟随、清屏、选择、复制和上下文截取。
- 导出全部、当前筛选、选中项、时间范围或指定上下文。
- TXT/LOG、JSONL、ZIP 诊断包和“复制给 AI”。
- 导出预览与可选脱敏。
- 简体中文、英文、浅色和深色主题。
- GitHub Releases 版本检查。

### 4.2 1.0 不包含

- 多设备并行采集。
- 自动保存或恢复历史日志会话。
- 云同步、账号、团队服务端或日志上传。
- APK 安装、文件浏览、断点调试、性能分析或 Android Studio 替代能力。
- 内置 AI 模型或调用第三方 AI API。
- Intel Mac、Windows 或 Linux 支持。
- 未经验证的 ADB 二进制再分发。

## 5. 核心使用流程

### 5.1 首次启动

1. 应用检查受管 ADB 是否存在且版本、校验值有效。
2. 若不存在，显示“准备连接组件”，说明文件来自 Google 官方 Platform-Tools，并要求用户确认适用许可。
3. 下载固定版本归档，验证文件大小与 SHA-256，安全解压到 Application Support。
4. 启动 ADB server，进入设备连接页。
5. 下载失败时允许重试、选择已有 ADB，或打开离线帮助。

### 5.2 连接设备

- USB：自动检测；未授权时提示用户在手机上允许此电脑；未开启调试时显示图文步骤。
- 无线：引导用户在 Android 无线调试页面找到配对码、IP 和端口，分别完成 `pair` 与 `connect`。
- 同时发现多台设备时要求用户选择一个活跃设备，不自动猜测。
- 设备掉线后保留当前日志与筛选，后台尝试重连。

### 5.3 选择应用

1. 应用选择器优先显示常用应用。
2. 其后显示设备上的第三方应用。已在公开、团队或用户配置中定义的应用显示名称和图标；未知应用显示通用图标和包名。
3. 用户可搜索或临时输入包名。
4. 选择后自动开始采集和筛选；应用未运行时显示“等待应用启动”，并提供一次标准启动尝试。

### 5.4 查看与分享

1. 默认进入“全部”应用日志，可一键切换警告、错误或业务库预设。
2. 普通搜索直接输入；高级面板提供排除、正则、大小写和来源条件。
3. 用户向上滚动时仅停止自动跟随，后台继续采集。
4. 导出时选择范围、格式和脱敏规则，预览后写入文件或剪贴板。

## 6. 信息架构与交互

### 6.1 主窗口

主窗口采用单窗口聚焦布局，不保留常驻侧栏。

- 顶部连接栏：设备状态、应用选择器、暂停、清屏和导出。
- 快捷筛选栏：全部、警告、错误、业务库、固定的用户预设和搜索框。
- 日志区：时间、等级、来源、消息四列的虚拟化列表。
- 状态区：当前筛选、总量/可见量、缓存回收、连接和自动跟随状态。

对已配置常用应用，包名只在详情或高级模式中显示；未知应用以包名作为主标识。设备序列号、PID、原始 ADB Tag 和原始行只在详情或高级模式中显示。

### 6.2 日志行为

- Warning 和 Error 使用克制但清楚的语义色；颜色不是唯一辨识手段。
- Java/Unity 多行堆栈作为一个事件，可折叠和展开。
- 超长消息默认折叠，按需渲染全文。
- 单击选中，双击展开；支持 Shift/Command 多选和右键操作。
- 用户向上滚动后显示“新增 N 条”，点击回到底部并恢复跟随。
- 暂停只冻结界面更新；采集、缓存和缓存上限仍然生效。
- 清屏开始新的内存会话段，不执行设备级 `logcat -c`，避免意外清除其他工具需要的系统日志。

### 6.3 筛选可见性

- 所有生效条件以可删除的 Chip 显示。
- 多个条件不会隐藏在不同弹窗中；高级面板关闭后仍显示摘要。
- “重置筛选”恢复当前应用的全部等级，不改变设备、应用或原始缓存。
- 非法正则在输入处提示并保持上一个有效规则。

### 6.4 快捷键

| 操作 | 快捷键 |
| --- | --- |
| 搜索 | `⌘F` |
| 清屏 | `⌘K` |
| 暂停/继续 | `Space`（焦点不在输入框时） |
| 导出 | `⌘E` |
| 复制给 AI | `⌘⇧C` |
| 回到底部 | `⌘L` |

## 7. 技术方案

### 7.1 技术栈

- Swift 6 与 Swift Concurrency。
- SwiftUI 构建应用壳、工具栏、设置和引导流程。
- AppKit `NSTableView` 或等价虚拟化组件渲染高频日志列表。
- Foundation `Process` 与 `Pipe` 管理 ADB 子进程。
- XCTest 和 XCUITest 完成单元、集成与 UI 测试。

选择原生方案的原因是产品只支持 Apple Silicon macOS，原生实现能获得最低运行开销、最一致的系统交互和最少的运行时依赖。Tauri 2 是未来跨平台需求明确时的备选；Electron 因嵌入 Chromium/Node 和多进程开销不符合轻量目标。

### 7.2 模块边界

| 模块 | 职责 | 主要依赖 |
| --- | --- | --- |
| `ADBRuntime` | 安装、验证、选择和启动 ADB；执行命令白名单 | Foundation |
| `DeviceService` | 设备状态机、USB/无线连接、授权与重连 | ADBRuntime |
| `AppCatalog` | 查询设备包名与 PID 集合，并合并配置中的应用名称和图标 | DeviceService, ConfigurationStore |
| `LogSession` | 管理单设备内存会话与有界缓存 | DeviceService, LogParser |
| `LogParser` | 流式解析、UTF-8 分块、多行合并和业务 Tag 提取 | 无 UI 依赖 |
| `FilterEngine` | 编译和执行筛选规则，维护可见事件索引 | LogSession |
| `LogViewport` | 虚拟化列表、选择和自动跟随 | FilterEngine |
| `ExportService` | 快照、脱敏、预览和多格式输出 | LogSession, FilterEngine |
| `ConfigurationStore` | 三层配置合并、导入导出与迁移 | Foundation |
| `AppDiagnostics` | 工具自身的本地诊断 | Foundation |

模块通过类型化接口传递数据；ADB 命令、解析、筛选和导出均不依赖 UI，可独立测试。

### 7.3 数据流与并发

```text
Android Device
      ↓
ADB child process
      ↓ byte chunks
LogParser actor
      ↓ LogEvent batches
LogSession actor → bounded ring buffer
      ↓ event indexes
FilterEngine actor
      ↓ 50–100 ms UI batches
SwiftUI state + AppKit viewport
      ↘ snapshot → ExportService task
```

- ADB 标准输出必须持续读取，不能因 UI 暂停或导出阻塞管道。
- UTF-8 解码器跨读取块保留不完整字节。
- 解析器输出不可变 `LogEvent`；筛选结果只保存索引，不复制正文。
- UI 每 50–100 毫秒或达到批量阈值时更新一次，避免逐行刷新。
- 导出从明确的事件边界生成一致性快照，采集可并行继续。

### 7.4 日志事件模型

每个 `LogEvent` 至少包含：

- 单调递增会话序号
- 设备时间与接收时间
- PID、TID、优先级、Android Tag
- 解析后的消息正文与原始文本
- 可选业务 Tag，例如 `[NetworkManager]`
- 多行/堆栈标识
- 当前已知包名与进程名
- 解析状态：完整、部分、原始行

日志格式以 `adb logcat -v threadtime` 为基础。解析失败的输入保留为原始事件，不能静默丢弃。

### 7.5 进程跟踪与采集范围

- `AppCatalog` 优先用受支持命令解析包名对应 PID，并以 `ps` 兼容路径补充。
- PID 集合包含主进程和以 `包名:` 开头的子进程。
- 应用启动、停止或重启时自动更新映射。
- 会话在有界缓存内保留设备原始日志；“当前应用”是默认筛选视图，因此切换全设备或其他预设不会破坏缓存。
- 若日志量过大触发回收，状态区明确显示最早保留时间和已回收数量。

## 8. 性能与资源边界

默认环形缓存同时受两个上限约束：

- 100,000 个 `LogEvent`
- 估算日志正文 128 MB

任一上限达到后淘汰最旧事件。用户可调整但不能关闭保护。淘汰计数和最早保留时间必须可见，导出不得声称包含已经回收的数据。

性能验收目标：

- 持续处理每秒 5,000 条日志。
- 处理每秒 20,000 条的短时突发而不阻塞 UI。
- 默认满缓存场景总内存约 250 MB 内。
- 正常滚动、搜索输入和暂停操作保持响应。
- 大文件导出不停止采集。

如果设备日志持续超过处理能力，优先持续读取和缓存，降低 UI 更新频率；仍无法承受时显式报告丢弃数量。

## 9. 筛选设计

### 9.1 规则能力

一个命名筛选方案可组合：

- 最低或指定日志等级
- Android 原生 Tag
- 消息业务 Tag
- 包含关键词与排除关键词
- 正则表达式与大小写策略
- 当前应用、指定包名或全设备范围
- 事件前后 N 条或指定秒数的上下文

规则先编译再生效。正则在后台执行，限制模式长度和单批工作量，并允许取消。

### 9.2 公开默认预设

- 当前应用全部日志
- Unity 日志
- 仅警告与错误
- 崩溃、异常与 ANR
- 网络相关通用关键词

### 9.3 IncentiveEngine 团队预设

IncentiveEngine 的 `LogUtils` 使用 `[Tag]: message` 格式，并有 `[IAA] message` 特例。团队构建配置包含以下逻辑分组：

- 全部业务日志：识别已知 `[Tag]:` 前缀。
- 网络：`NetworkManager`、`NetworkDelegate`、`NetworkUtils`。
- 广告：`IAA` 和团队广告插件 Tag。
- 数据：`EventTracker`、`FirebaseAnalyticsTracker`、`GameAnalytics`。
- 任务与奖励：`Task*`、`RewardLogger`。
- 提现：`Withdraw*`、`PaymentInputPanel`。
- UI 与配置：`UIManager`、`CloudConfigManager`、主题和资源 Tag。

具体列表来自团队构建配置，不硬编码进公开源码。

## 10. 配置系统

### 10.1 三层配置

合并优先级从低到高：

1. `PublicDefaults.json`：提交到公开仓库，只有通用预设。
2. `TeamDefaults.json`：构建时由仓库外输入文件生成的包内只读资源，内部安装包可包含。
3. `UserConfig.json`：保存在 Application Support，保存用户新增、覆盖和隐藏状态。

条目使用稳定 UUID 或命名空间 ID。高优先级同 ID 条目覆盖低优先级；用户可隐藏内置项，但不能修改应用包内资源。配置升级不覆盖用户层。

### 10.2 构建隔离

- 本地团队构建输入默认路径 `Config/TeamConfig.json` 被 `.gitignore` 排除；构建验证后将其复制为包内 `TeamDefaults.json`。
- CI 通过显式参数传入团队配置，不能自动搜索本机文件。
- 公开 Release 工作流必须设置 `distribution=public`，并在发现非空团队资源时失败。
- 构建产物生成配置来源摘要，便于核验公开包不含内部条目。

### 10.3 导入与迁移

- JSON 顶层包含 `schemaVersion`、导出应用版本和内容类型。
- 导入前验证结构、字段长度、正则和条目数量。
- 预览新增、覆盖、跳过和冲突数量，用户选择合并或替换用户层。
- 已知旧版本由纯函数迁移器逐级升级。
- 高于当前支持版本的配置拒绝导入并解释原因。
- 未知非关键字段在往返导出时尽量保留，便于前向兼容。

## 11. ADB 获取与管理

### 11.1 公开版策略

公开版不直接打包 Google 发布的 Platform-Tools 归档。首次使用时：

1. 从版本化清单读取官方 URL、版本、大小和 SHA-256。
2. 展示 Google 来源、适用许可和下载大小。
3. 用户确认后通过 HTTPS 下载到临时目录。
4. 校验后安全解压，将受管版本原子安装到 Application Support。
5. 只执行受管 `adb`，不执行归档内无关工具。

Google SDK 许可原则上限制 SDK 的复制与再分发；ADB AOSP 源码采用 Apache-2.0，但不能据此假设 Google 的完整预编译 Platform-Tools 归档可以自由再分发。公开发布前仍应进行许可证复核。

### 11.2 版本与回退

- 版本清单固定具体稳定版本，不在运行时盲目追随 `latest`。
- 新 ADB 版本先经过设备回归测试，再更新清单。
- 保留一个已验证旧版本用于更新失败时回退。
- 高级设置允许选择已有 ADB；保存前验证架构、版本和可执行性。
- 内部团队若嵌入二进制，必须使用独立构建开关并自行确认分发权限。

## 12. 导出与脱敏

### 12.1 导出范围

- 当前缓存内的全部事件
- 当前筛选结果
- 用户选中事件
- 起止时间范围
- 某事件前后指定条数或秒数

预览显示范围、事件数、最早/最晚时间、预计大小、已回收数量和脱敏命中数。

### 12.2 格式

- `.log` / `.txt`：带稳定头部的可读文本。
- `.jsonl`：每个事件一行，字段版本化，适合程序和 AI 处理。
- `.zip`：包含日志、环境摘要、筛选说明、格式版本与许可说明。
- 剪贴板 Markdown：面向 AI，包含问题填写区、环境、筛选条件和关键日志。

“复制给 AI”使用明确字符预算。超限时优先保留 Error、Warning、堆栈及其上下文，并在文本中写明省略规则和省略数量，禁止无提示截断。

### 12.3 脱敏

- 只处理导出副本，不修改内存原始事件。
- 内置常见 Token、邮箱、手机号、IP/设备标识模式。
- 用户可添加正则规则和替换文本。
- 预览高亮命中并显示数量。
- 明确提示脱敏是辅助能力，不能保证识别所有敏感信息。
- 诊断环境默认排除设备序列号、完整本机路径和无线地址。

## 13. 错误处理

| 场景 | 行为 |
| --- | --- |
| ADB 未安装或损坏 | 阻止执行，提供重新下载或选择已有 ADB |
| 下载或校验失败 | 删除无效临时文件，显示来源、网络或校验错误并允许重试 |
| 设备 `unauthorized` | 提示在手机上允许此电脑，并持续检测状态 |
| 设备 `offline` 或掉线 | 保留会话，按退避策略重连 |
| ADB 意外退出 | 记录自身诊断，按 1、2、5、10 秒退避重启 |
| 应用未运行 | 保持等待并刷新 PID；提供标准启动尝试 |
| 日志解析失败 | 保存为未解析原始事件 |
| 缓存达到上限 | 淘汰最旧事件并显示数量、最早保留时间 |
| 非法或过慢正则 | 不启用新规则，保留上一个有效规则并允许取消 |
| 导出磁盘不足/无权限 | 保留当前会话，清理无效临时文件并说明恢复方法 |
| 配置版本过新 | 拒绝导入，不修改现有配置 |

## 14. 安全与隐私

- ADB 调用使用可执行文件路径和参数数组，禁止 Shell 字符串拼接。
- 命令经过内部白名单；UI 不提供任意命令执行入口。
- 下载使用 HTTPS、固定清单、大小限制和 SHA-256 校验。
- ZIP 导入拒绝绝对路径、`..`、符号链接和解压体积异常。
- 外部文本、包名、地址、端口、路径和配置字段均有格式及长度限制。
- 应用不申请管理员权限，不监听网络端口，不收集遥测。
- 直接分发版本不启用 App Sandbox，以允许受控启动 ADB 和访问用户选择的导出路径；仍启用 Hardened Runtime，并将系统能力限制在实际需要范围内。
- ADB server 由 ADB 自身按正常机制管理；应用退出时只停止自己启动的日志子进程，不强制终止用户其他 ADB 工作流。
- `AppDiagnostics` 不记录设备日志正文、脱敏前导出正文或剪贴板内容。
- 仓库包含 `SECURITY.md`、第三方许可证、NOTICE 和依赖更新策略。

## 15. 测试与质量门槛

### 15.1 单元测试

- Logcat 分块、跨块 UTF-8、多行堆栈、时区/日期边界、异常行和超长行。
- 业务 Tag 提取、PID 映射、筛选组合、正则取消和上下文选择。
- 环形缓存的双上限、回收计数和快照一致性。
- 脱敏规则、导出格式快照和 AI 字符预算。
- 配置合并、冲突、迁移、未知版本和恶意输入。

### 15.2 集成测试

使用 Fake ADB 可执行程序模拟：

- 无设备、单设备、多设备、未授权、离线和状态变化。
- USB 与无线配对成功/失败。
- 命令超时、异常退出、碎片化输出和持续日志洪峰。
- 应用启动、停止、PID 更换和子进程出现。
- 下载失败、错误校验值、回退版本和系统 ADB 选择。

### 15.3 UI 与人工测试

- 首次启动到看到日志的完整流程。
- 筛选可见性、键盘操作、VoiceOver、浅色/深色和中英文布局。
- 自动跟随、向上滚动、暂停、清屏、选择和导出。
- Android 8+ USB 验证，Android 11+ 无线配对验证；发布前覆盖团队常用设备和当前主流 Android 版本。
- 数小时 soak test、断线循环、大日志和低磁盘空间测试。

### 15.4 CI 门槛

- 编译警告视为失败。
- 单元与集成测试全部通过。
- 格式化、静态分析、许可证与依赖漏洞检查通过。
- 性能基准不得超过约定回退阈值。
- 公开构建的团队配置泄漏检查通过。

## 16. 发布与更新

### 16.1 无 Apple Developer 账号阶段

- GitHub Actions 产出 arm64 ZIP 和 DMG、SHA-256、变更日志、第三方 NOTICE 和 SBOM。
- Release 明确标识“未公证构建”。
- 安装说明使用 macOS“系统设置 → 隐私与安全 → 仍要打开”，不要求关闭 Gatekeeper 或删除隔离属性。
- 应用检查 GitHub Releases 后提示新版本并打开下载页，不静默替换自身。

### 16.2 获得 Developer ID 后

- 启用 Hardened Runtime、Developer ID 签名、Apple 公证和票据装订。
- 对 `.app` 内所有可执行文件和辅助二进制按内到外顺序签名。
- 公证与 Gatekeeper 验证成为 Release 阻断门槛。
- 评估 Sparkle 或等价更新方案；启用前必须具备独立更新签名、回滚和完整性测试。

### 16.3 版本管理

- 应用使用语义化版本。
- 配置与 JSONL 格式拥有独立 `schemaVersion`。
- ADB 清单单独版本化并记录验证设备矩阵。
- 建议项目采用 Apache-2.0 许可证。

## 17. 可访问性与本地化

- 所有状态颜色同时配有文字或图标。
- 关键操作有稳定的 VoiceOver 标签和键盘路径。
- 日志字体大小、行高和是否自动换行可调。
- 中文与英文文案使用字符串目录管理，不在视图中硬编码。
- 日期、时间、数字和文件大小遵循系统区域设置；导出结构化字段保持稳定、与语言无关。
