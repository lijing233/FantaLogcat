# FantaLogcat 交互优化与开源收尾设计

- 状态：已确认，待书面规格审阅
- 日期：2026-08-12
- 目标：优化日志搜索与设置提交语义，完成一次聚焦的交互审查，并把本地仓库补齐到可公开、可持续验证的状态。
- 不在范围：创建或配置远程仓库、推送代码、签名或公证应用、发布 GitHub Release、重构日志查询语法。

## 1. 搜索与筛选交互

日志页保留当前“关键词标签 + OR/AND 关系”的查询模型，但重新安排操作层级。输入框和“添加”组成主要操作区；“添加”必须同时显示图标与文字，使用大号控件尺寸，并保持 Return 提交。收藏当前输入、选择下一个关键词关系、清除条件属于次级操作，必须有文本、帮助提示或清晰的无障碍名称，不能依赖难以发现的小图标。

关键词标签继续水平展示已有查询关系，单个移除按钮必须满足易点击要求。常用关键词在可用宽度不足时换行，而不是被窗口裁掉。空输入不能添加或收藏；重复添加继续按用户明确操作保留，不引入自动去重或复杂查询编辑器。

“清除筛选”是单一、一致的动作：同时清空等级筛选、已添加关键词、查询模型和尚未提交的输入草稿，并恢复“全部日志”。日志结果为空时提供的清除按钮和搜索区清除按钮调用同一语义。搜索区域要为键盘用户提供明确路径：Return 添加，Escape 优先清空输入草稿；现有查询仍由显式清除动作移除。

## 2. 设置事务语义

设置页打开时从 `AppModel` 创建独立草稿，包含界面语言与完整 `LogCaptureSettings`。所有 Picker、Stepper 和 Toggle 只写入草稿；设置页打开期间不得写入 `UserDefaults`，也不得改变主窗口使用的配置。

设置页内容按照草稿语言即时预览，以便用户确认语言选择；主窗口仍维持已保存语言，直到保存。点击“保存”时一次性规范化并提交语言及日志设置，然后关闭页面。点击“关闭”、按 Escape 或通过系统关闭路径结束设置页时丢弃全部草稿。关闭操作不显示二次确认，因为没有持久副作用；再次打开时重新从当前已保存配置创建草稿。

保存是唯一默认动作，并使用明确的“保存”文案；“关闭”是取消语义，不能使用含糊的“完成”。模型提供一个原子意图方法来提交设置，UI 不直接组合多个持久化调用。

## 3. 聚焦的体验审查

本轮只修复与日志排查主流程直接相关的问题：

- 搜索、筛选、清屏、导出和设置按钮具有足够点击区域、清晰层级、帮助提示及无障碍名称。
- 筛选控件在最小窗口宽度下不能静默截断；必要时允许横向滚动或自适应换行。
- 空结果状态必须提供能真正恢复结果的清除动作，并同步所有 UI 草稿状态。
- 危险或不可逆动作不得伪装成默认操作；清屏继续保持禁用态反馈，不新增无必要的确认弹窗。
- 中英文文案保持一致语义；不在本轮引入新的视觉主题、导航架构或高级查询弹窗。

## 4. 开源仓库收尾

仓库根目录新增以下公开文件：

- `README.md`：产品定位、功能、系统要求、安装与 Gatekeeper 提示、ADB 受管下载及校验、隐私模型、源码构建、测试、已知限制、贡献与安全入口。
- `LICENSE`：未经修改的 Apache License 2.0 正文。
- `NOTICE`：项目版权说明以及对 Android Debug Bridge / Android Open Source Project 的必要归属，不暗示 Google 背书。
- `CONTRIBUTING.md`：开发环境、XcodeGen/Mint、分支与提交约定、测试命令、私有配置隔离要求。
- `SECURITY.md`：受支持版本与私密漏洞报告流程；若尚无公开安全邮箱，则使用 GitHub Private Vulnerability Reporting 作为唯一公开入口，不编造联系方式。
- `CODE_OF_CONDUCT.md`：Contributor Covenant 2.1 正文及基于 GitHub 私密渠道的执行说明。
- `.github/ISSUE_TEMPLATE/bug_report.yml`、`feature_request.yml`、`config.yml` 和 `PULL_REQUEST_TEMPLATE.md`：收集版本、macOS、设备连接方式、复现步骤、隐私确认与验证清单。
- `.github/workflows/ci.yml`：在受支持的 macOS Runner 上生成工程、运行单元测试、构建 Release，并执行公开仓库/产物检查。
- `docs/RELEASE_CHECKLIST.md`：真实设备、隐私、构建、校验和、签名/公证与人工发布步骤。

CI 与发布脚本必须检查 `Config/TeamConfig.json` 不存在于公开源码和应用产物；检查必需文档存在；生成 arm64 Release ZIP 及 SHA-256 文件。自动化不得持有发布凭据，也不得自动创建 Release。

## 5. 架构边界

`SettingsView` 负责展示和编辑一个值类型草稿，不负责持久化。`AppModel` 继续拥有当前有效语言和采集设置，并新增单一提交入口；现有 `setLanguage` 与 `setCaptureSettings` 可收窄为提交入口的内部实现，避免 UI 产生部分提交。

搜索构建器暂时保留在 `LogView`，但将清除、添加和布局语义整理为小型私有方法或可独立测试的值类型。若为了测试需要抽取状态，抽取范围只覆盖关键词草稿、选中条件和清除行为，不扩展查询语言。

仓库检查脚本放在 `Scripts/`，Makefile 只编排稳定命令；GitHub Actions 调用与本地相同的 Make 目标，避免 CI 与开发者流程分叉。

## 6. 错误处理与反馈

设置保存使用当前本地同步存储，正常情况下无需进度状态；编码失败时不得静默宣称成功。由于现有 `UserDefaults` 写入 API 不报告磁盘错误，本轮把可编码性通过单元测试覆盖，并保持保存动作确定性。

CI 或公开构建检查发现私有配置、缺失文档、错误架构、缺失可执行文件或无效代码签名结构时立即失败并输出具体文件/检查项。文档明确未签名本地构建可能触发 Gatekeeper，并只描述通过“系统设置”确认打开的标准流程，不建议用户全局关闭安全机制。

## 7. 测试与验收

领域测试先失败再实现，覆盖：设置草稿不改变模型、关闭丢弃全部字段、保存一次性应用语言与采集设置、配置规范化，以及搜索清除同时重置等级和关键词状态。UI 层为“添加”“保存”“关闭”“清除筛选”提供稳定 accessibility identifier，并至少覆盖设置关闭不保存、设置保存生效和搜索添加/清除主路径。

完成标准：

1. `make test` 全部通过。
2. `make release` 生成可验证的 arm64 ZIP 与 SHA-256。
3. 公开仓库检查通过，源码与应用产物均不包含团队私有配置。
4. 在 920×600 最小窗口、中英文界面和浅深色外观下人工检查日志搜索与设置页。
5. README 中的本地构建命令能够从干净检出复现；正式发布仍须用户在真实 Android 设备上完成 Release Checklist。
